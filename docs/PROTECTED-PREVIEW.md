# Share a password-protected EchoFrame preview

This route uses a private GitHub repository and a separate Render web service. Your team gets an HTTPS website address and a shared preview password. No OneDrive account is needed. The service has been prepared and tested locally; it has not been deployed.

## 1. Prepare the files

Use `EchoFrame-protected-preview.zip`, generated by `python scripts/package_preview.py`. Extract it into a new folder. It contains the current built website, its password-protected server, and a `render.yaml` configuration. It excludes internal research documents, drafts, development tools, local credentials, and the existing repository's history.

For subsequent updates, run `python scripts/build.py` before regenerating the package.

## 2. Put the package in a private GitHub repository

1. Sign in to [GitHub Desktop](https://desktop.github.com/).
2. Choose **File → New repository**. Name it `echoframe-team-preview` and choose a location on your computer.
3. Copy the **contents** of the extracted preview folder into that new repository folder. `render.yaml`, `preview_server.py`, and `public` should be directly inside the repository, not inside an extra nested folder.
4. In GitHub Desktop, enter a summary such as `Add team preview`, then click **Commit to main**.
5. Click **Publish repository**, leave **Keep this code private** checked, and publish.

Use GitHub Desktop for the upload because the included video is too large for GitHub's browser file uploader. These are snapshot files, so the full website build tools are not required on Render.

[GitHub's repository setup instructions](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop) describe creating and publishing a private repository.

## 3. Deploy it on Render

1. Create or sign in to a [Render account](https://dashboard.render.com/).
2. Select **New → Blueprint**, connect GitHub, and choose `echoframe-team-preview`.
3. Keep **Blueprint Path** as `render.yaml`.
4. Review the `echoframe-team-preview` web service and its Free instance plan, then click **Deploy Blueprint**.
5. Wait for the service to become Live. Open its `https://…onrender.com` address.

The package already specifies the build and start commands. Use the Blueprint flow so the password and application secret are generated automatically. It does not need an email service or a custom domain for review.

[Render's Blueprint setup guide](https://render.com/docs/infrastructure-as-code) covers the deployment flow. The selected [Free web service](https://render.com/docs/free) sleeps after 15 idle minutes and may take about a minute to wake. Included bandwidth and build limits apply.

## 4. Get the login and share it

In your Render service, open **Environment** and reveal the `PREVIEW_PASSWORD` value. The username is **team**. The browser asks for these details before it loads the website. Render [generates the random password](https://render.com/docs/blueprint-spec#generating-random-secrets) from the configuration; no password is committed to GitHub.

Test the link in a private/incognito window. It should request a username and password. Then share the HTTPS URL and login with your team through your usual internal channel. They do not need GitHub or Render accounts to view the site.

This is shared-password access, not individual accounts. Anyone with the login can open the preview. To change access, replace `PREVIEW_PASSWORD` in Render Environment with a strong new password of at least 16 characters and deploy the change. The old password will stop working for subsequent requests. Close the private browser session when finished reviewing.

## Updates and practical limits

- Website changes: regenerate the package, replace the repository's `public` folder with the new one, commit and push in GitHub Desktop, then use **Manual Deploy → Deploy latest commit** in Render. Code auto-deploys are disabled in this package. Blueprint configuration changes can still trigger a deployment through Blueprint synchronization.
- The preview protects pages, assets, video ranges, downloads, redirects, and the contact API. Only a health endpoint that returns `{"ok": true}` is available without a login. Responses tell browsers not to cache and crawlers not to index the preview.
- With no email credentials, the contact form offers its email-link fallback. To enable direct sending later, configure Resend and set `PUBLIC_ORIGIN` to the exact preview origin. Render's Free services block common SMTP ports; use an HTTPS mail provider or a hosting plan that supports your SMTP connection.
- Keep the preview on its separate Render address. It does not replace the live EchoFrame domain.

## Maintainer checks

```powershell
python scripts/test_preview_access.py
python scripts/test_contact.py
```

These checks cover missing, wrong, malformed, and rotated credentials; access to pages and assets; private-file exclusion; video byte ranges; cache and indexing headers; and the existing contact service. They do not send email.
